# Граница между исследованием и API mini-games-kit

**Этот пакет — справочник, а не новая зависимость и не runtime-система.** Добавление документа не означает, что какая-либо функция экспортирована или доказала полезность в потребителях.

## Сначала повторно используйте существующие механизмы

| Исследовательская задача | Что уже можно проверить в kit | Что остаётся в игре |
| --- | --- | --- |
| Честная выдача и воспроизводимость | [RandomSource / pickWeighted](../core/RANDOM.md) | Генератор, solver, правила уровня, баланс, политика сложности |
| Feel и ожидание наград | [Presentation skip](../core/PRESENTATION_SKIP.md), [Value transfer](../core/VALUE_TRANSFER.md), [Pointer response](../feel/POINTER_RESPONSE.md), [Pitch](../audio/PITCH.md), [Audio mixer](../audio/PRESENTATION_MIXER.md) | Семантика успеха, эффекты, ресурсы, тайминги и художественное направление |
| Daily, прогресс, повторное посещение | [Daily streak](../core/DAILY_STREAK.md), [Tier progress](../core/TIER_PROGRESS.md), [Hint budget](../core/HINT_BUDGET.md) | Причина возвращения, календарные правила, критерии наград, UX следующей цели |
| Сохранения и earned rewards | [JSON repository](../platform/JSON_REPOSITORY.md), [Revision snapshot](../platform/REVISION_SNAPSHOT_QUEUE.md), [Durable receipt](../platform/DURABLE_RECEIPT_QUEUE.md) | Save schema, идентичность партии, экономика и пользовательские решения |

Ничего из перечисленного не доказывает наличие универсального Experience/Novelty/Challenge/Motivation Director в kit. Такого публичного API **нет**.

## Изоляция владения

- **Domain/game:** решает, какой ход допустим, какой прогресс сохранён и когда заработано вознаграждение.
- **Presentation:** показывает результат; не является источником gameplay/durable-state.
- **Platform:** безопасно управляет активностью, SDK, хранилищем и внешними receipts.
- **Research / design policy:** выбирает и оценивает гипотезы; не владеет чужими сохранениями, контентом и рекламными ID.

## Когда допустимо извлекать новое в kit

1. Не менее **двух независимых проектов** встретили одинаковую устойчивую задачу.
2. Локальные реализации уже проверены на настоящем consumer-сценарии.
3. Общая абстракция уменьшает дублирование/ошибки, а не создаёт новый конфигурационный монолит.
4. Новая функция имеет явные non-goals, API-документ, тесты и правила жизненного цикла.
5. Баланс, художественная идентичность, наборы уровней, частота рекламы и контент остаются в игре.

До выполнения этих условий сохраняйте решение в consumer. **Документирование альтернативы HOLD — нормальный положительный результат.**

## Правила внедрения для агента

1. Сначала [выбрать направление](PROJECT_SELECTION.md).
2. Проверить [действующий API](../API.md) и связанные production playbooks, чтобы не дублировать готовое.
3. Изменять только consumer, если вопрос — о геймдизайне одного продукта.
4. Не соединять переключатели «игра сложнее», «больше рекламы» и «красивее награда» в одну неразделимую интервенцию.
5. Гейт релиза / реальной приёмки остаётся в game repo; документы исследования не являются подтверждением работы на устройстве.

**На текущем этапе:** только документация. Никаких новых package exports, зависимостей, runtime defaults и изменений bootstrap от добавления этого корпуса не требуется.
