# Visual Direction & UX Preproduction

**Статус:** методология принятия проектных решений для небольших игр. Это не художественный стиль по умолчанию, не SDK, не новая runtime-зависимость и не разрешение на производство дорогостоящего контента.

## Зачем

До массового изготовления интерфейса, ассетов, анимаций и магазинных материалов агент должен уметь показать владельцу **несколько цельных, технически реализуемых вариантов одной и той же игры**: сеттинг, визуальные правила, возможный маскот, реальные игровые экраны, UX, иконка, звук/движение, стоимость и риски.

Агент выбирает **направления для рассмотрения**, но пользователь утверждает конечный арт-дирекшен. **Два прохода стоимости:** сначала 2–3 дешёвых сравнимых концепта (реальный gameplay state + icon + style/mascot sample), затем полная экранная матрица только у 1–2 финалистов. Для дорогой high-stakes игры можно заранее согласовать глубокий режим со всеми вариантами. Никакой «модный стиль», яркая палитра, сюжет, зверушка или 3D не обязательны.

## Порядок работы

1. **[METHOD.md](METHOD.md)** — узнать задачу, изучить референсы, разложить продукт на независимые решения, подготовить 2–3 цельные концепции, оценить и утвердить.
2. **[SETTING_AND_MASCOT.md](SETTING_AND_MASCOT.md)** — отдельно выбрать, нужен ли сеттинг и персонаж, какую роль они выполняют, сколько реально стоят, как сохранить узнаваемость.
3. **[UX_AND_ART_SYSTEM.md](UX_AND_ART_SYSTEM.md)** — UX-first, экраны, layout, визуальные токены, мобильная читаемость, движение, звук, графический pipeline и ограничения.
4. **[AGENT_PROTOCOL.md](AGENT_PROTOCOL.md)** — обязательный формат результата агента: visual pitches, comparison sheet, кандидаты, верификация, согласование.
5. **[CONCEPT_PITCH_TEMPLATE.md](CONCEPT_PITCH_TEMPLATE.md)** — карточка каждого варианта.
6. **[ART_BIBLE_TEMPLATE.md](ART_BIBLE_TEMPLATE.md)** — краткая спецификация согласованного направления для реализации.
7. **[EXAMPLE_ASSOCIATIONS.md](EXAMPLE_ASSOCIATIONS.md)** — пример вариантов для гипотетической игры; не является новым ТЗ существующему проекту.
8. **[EVIDENCE.md](EVIDENCE.md)** — проверяемые внешние источники, ограничения переноса и уроки из наших репозиториев.

## Правило для новых проектов

**До массового art production и финальной skin-реализации нужно зафиксировать выбранную визуальную стратегию.** Для этого агент готовит минимум два сопоставимых варианта, обычно три. Но сначала нужна понятная механика и нейтральный UX-каркас: красивый рендер не доказывает играбельность.

Утверждение направления — **важный этап проектирования**, но это не требование создать сюжет, маскота, 3D, сложную мету или все экранные иллюстрации. Для крайне простой игры результат может занимать одну страницу и показывать два ясных минималистичных направления.

Для позднего косметического фикса, UX-аудита или переноса кода этап с концепциями можно не повторять; ориентироваться на уже принятое направление. Большой редизайн снова проходит сравнительный gate.

## Чего требовать от агента

- Не просто «минимализм / казуал / премиум», а **одни и те же реальные игровые состояния** для всех концепций.
- В каждом варианте: UX-сетка, игровой объект, визуальная грамматика, настроение, маскот **да/нет и зачем**, иконка, два-три характерных момента, ориентировочная стоимость.
- **Один из вариантов без маскота** или явно документированная причина не включать такой baseline. Маскот не должен закрывать поле.
- Отдельно показать минимальный экран, перегруженный/сложный экран, победу, меню и магазинную иконку; текст и кнопки должны оставаться настоящими, не заменёнными красивой рекламной иллюстрацией.
- В конце — авторская рекомендация агента **с доводами и рисками** и запрос решения владельца, а не автоматический выбор по сумме субъективных баллов.

## Что происходит после выбора

Зафиксировать арт-дирекшен через [ART_BIBLE_TEMPLATE.md](ART_BIBLE_TEMPLATE.md), выполнить один вертикальный срез в настоящем движке и проверить живую компоновку, жесты, исходный и контрастный режимы, короткий экран, крупный текст, рекламу и реальное время подготовки ассетов. **Только после gate** масштабировать ассеты.

Новые production-приёмы сначала применяются внутри игры. В kit извлекаются лишь повторно доказанные технические примитивы, как описано в [границах Puzzle Design](../puzzle-design/INTEGRATION_BOUNDARIES.md).

**Основное правило:** выбрать визуальное направление — не значит перестать улучшать UX. После утверждения стабильны принципы, но доказанный дефект читаемости, поведения или доступности исправляют всегда.
