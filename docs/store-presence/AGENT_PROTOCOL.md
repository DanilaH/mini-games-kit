# Store Release Agent Protocol — от игрового билда до проверенной карточки

**Назначение:** агент должен уметь подготовить законченный комплект материалов для **согласованных** магазинов, объяснить варианты и подтвердить их корректность. Он не должен автоматически регистрировать аккаунт, запускать рекламу, менять опубликованные страницы или отправлять на модерацию без отдельного разрешения владельца.

## A. Восстановить исходный контекст

1. Открыть real game repo: current HEAD, README, decisions, release checklist, прежние store assets, локализации, текущую Art Bible.
2. Сверить со словами владельца **реальный статус публикации**: не верить старым «published» из README, если владелец сообщил обратное. **«Семечки» на 11.11.2026 не опубликованы и не отправлены на модерацию** по подтверждению владельца, хотя в старых docs это неверно.
3. Проверить фактический gameplay: первые минуты, основной жест, крайний контент, win/fail, daily/meta, доступность, рекламный слот, landscape только если поддерживается.
4. Составить фактический feature inventory: **реально есть / в разработке / планируется**; рекламировать только первый столбец.
5. Согласовать target stores, локали, типы устройств, release budget и права автора. Нет плана выхода в iOS/Google/Yandex → не делать полноценные комплекты.
6. Записать user promise, реальные отличия, ожидаемую эмоцию и риски ложного понимания жанра.

**Выход:** черновик [Store Brief](STORE_BRIEF_TEMPLATE.md), с точным SHA и release status.

## B. Исследовать ближайшее витринное окружение

1. Выбрать 4–8 актуальных **похожих по механике** игр в *каждой реальной целевой платформе* или использовать переносимые референсы с честной пометкой.
2. Для каждого — URL, дата, страна/локаль, searchable title, icon, first 3 screenshots, main description, feature/cover if available, realistic gameplay if verified.
3. Отделить **политику площадки** от **художественных приёмов конкурента**. Не копировать персонажа, отдельные картинки и формулировки.
4. Искать не только стиль, но и **какие обещания действительно подтверждаются gameplay**.
5. Отобрать 2–3 проверяемых гипотезы: «понятна ли механика в первом кадре», «иконка A больше напоминает реальную сортировку, чем иконка B».
6. Не объявлять лидера «лучшим по конверсии» на основании установок/рейтингов без доступа к его экспериментам.

**Выход:** reference grid с удачными и опасными приёмами, evidence type и ссылками.

## C. Предложить варианты, прежде чем полировать

Для маленькой игры — **низкая цена выбора**:
- 2 candidate icon/first-frame packages (не 10–20 декоративных перекрасок).
- А: основной предмет/игровая механика, самый честный baseline.
- Б: альтернативная визуальная гипотеза (реальный герой, необычный момент или другая компоновка) с объяснением.
- В исключительных случаях третий вариант, если действительно добавляет другое обещание.

**Галерея**: icon в размере store shelf; первый кадр без текста; первый кадр с кратким смысловым callout (если полезно); условная preview crop; одинаковый реальный игровой контент.

Оценить по: узнаванию жанра, правдивости, видимости действия, читаемости thumbnail, различимости в списке, cost полного пакета, риск отказа. **Не назначать «победителя» по красивой картинке**, представить свою рекомендацию и получить выбор владельца. Для уже утверждённого сильного направления — ограничиться проверкой baseline, не начинать необязательный редизайн.

**Выход:** выбранный storyboard и icon direction; статус APPROVED / PROVISIONAL / HOLD. Нет owner approval → не масштабировать.

## D. Производство оригиналов и экспорт

1. Отснять из **реального production gameplay renderer / APK**, не из AI-макета, оригиналы menu, core gameplay, dense gameplay, win, вариативность, при необходимости подсказки/мета.
2. Зафиксировать source commit, app version, device/viewport, locale, scene/seed/QA fixture, source SHA256, способ записи.
3. Сделать один «source-of-truth» storyline: состав кадров, факт и цель каждого, approved art identity.
4. Экспортировать **с разными настройками под store/page/device**: не растягивать поле, не обрезать смысл, придерживаться источников [platform matrix](PLATFORM_REQUIREMENTS.md).
5. PNG/JPEG и видео — только в поддерживаемых форматах. Отдельно оформлять Yandex cover и Google feature, даже если используются общие объекты.
6. Заполнить Google/RuStore/Apple/Yandex свои текстовые поля: не путать 80-char short с Apple subtitle 30; Apple keyword budget 100 **bytes**.
7. Сделать contact sheet на маленьком мобильном превью, проверить названия и реальную читаемость, риск усечения, crop и локаль.
8. Если требуются магазинные видео, подготовить свои orientation/duration/codecs, подтвердить отсутствие чужой рекламы и фейкового gameplay.
9. Не производить дополнительный tablet/TV/desktop/iOS формат без реальной поддержки и канала выпуска.
10. При необходимости выполнить [необязательный статический preflight](tools/README.md) и сохранить JSON-отчёт. Его PASS покрывает только параметры файлов и полей, но не real gameplay, crop, лицензии, form preview или модерацию.

**Выход:** оригиналы, platform exports, manifest/hashes, screenshot storyboard, text files. Не перегружать consumer repo гигабайтами ненужных binary artifacts; можно хранить в release assets, но указывать точное место.

## E. Независимая приёмка и ограничители

**Технический gate:**
- Целевая поверхность, target locale, формат/alpha, размеры/ratio, bytes, count, видео duration совпадают с актуальными official docs.
- Иконка/приложение не противоречат друг другу и policy.
- В RuStore checked: main vs custom page; min3 per uploaded device; portrait cropping conflict; поля из реальной формы.
- В Google checked: icon PNG32, feature 1024×500, main min2, per-promo eligibility separately.
- В Apple checked: iPhone required screenshot sizes и iPad если заявлен; >half actual use; keywords 100 bytes.
- В Yandex checked: icon/cover, 2 screenshots per selected target platform, 70% real gameplay criterion/exception, title/SEO/how-to-play limits.

**Truth gate:**
- Ни один кадр не рекламирует несуществующую функцию, персонажа, трофей, валюту, количество уровней или устройство.
- Нарисованные рекламные композиции помечены отдельно от screenshot и не подменяют их.
- Все изображения оригинальны/лицензированы; нет чужого UI/наименований/брендов.

**Visual gate:**
- Показывать **три первых кадра в уменьшенном размере**, иконку рядом с 6–10 конкурентами, crop preview каждой заявленной поверхности, highlight главного жеста.
- В первые 5–10 секунд неподготовленный зритель способен назвать основной gameplay; это qualitative check, не процент CVR.
- Текст локализован, читается после уменьшения, не закрывает главное действие.

**Publishing gate:** изменение витрины, отправка на модерацию, платная рекламная кампания и запуск эксперимента — **только после явного согласования**. CI не доказывает, что магазин принял пакет; реальная console preview/moderation — отдельный evidence level.

## F. Итоговый отчёт владельцу

Не десятки страниц текста без картинок, а **короткий и проверяемый delivery report**:
1. Реальный статус игры и целевые магазины, собранный билд/commit.
2. Прямые ссылки на два concept candidates и рекомендация с trade-offs.
3. Preview галерея настоящих материалов: icon/screenshot/feature/cover + locale.
4. Какие exact files и тексты идут **в какой магазин**; почему нет остальных комплектов.
5. Сводка проверок PASS / BLOCKED / NEEDS CONSOLE CONFIRMATION с источниками.
6. Что новый сотрудник/агент не должен заново придумывать; где лежат masters и export settings.
7. План будущего эксперимента (если после запуска появится трафик).
8. Последний вопрос: **согласовать оформление / разрешить загрузку / разрешить модерацию / разрешить публикацию** — это *разные действия*.

## G. Точки возврата

- **Нет real gameplay capture:** сначала завершить релизно-представительный билд/исправить UI, не лепить фейковые screenshots.
- **Не ясно, какой store:** приоритет RuStore, если он прямо указан в source-of-truth; другие HOLD, не придумывать аккаунты.
- **Разные требования docs:** открыть current console, отметить discrepancy и не игнорировать более строгие.
- **Неясность art direction:** вернуться к [Visual Preproduction](../visual-preproduction/README.md) и показать 2 сравнимых concept slices, не перерабатывать продукт тайно.
- **Недостаточный трафик:** выбрать честный baseline, записать гипотезу в HOLD, не запускать бесконечные эксперименты.
- **Уже опубликованная игра:** сохранять текущие реальные branding/assets и release status, согласовывать изменение публичной карточки отдельно.

## H. Жанровые стартовые гипотезы — не задания на новые функции

| Проект | Что обычно показать первым | Потенциальная ошибка |
| --- | --- | --- |
| **Семечки / Number Match** | Чистая сетка, реальная пара, результат удаления | Превратить в абстрактную книгу наград, скрыв цифры |
| **Блоки** | Placement + line clear в честном board state | Маркетировать ещё не реализованный Adventure |
| **Стрелки** | Плотное поле и видимое освобождение стрелки | Огромные силуэты без понятного действия |
| **Сортировка воды** | Переливание и удовлетворительный момент сортировки | Заменить gameplay рисунком лаборатории |
| **Дороги** | Заполненный маршрут, поворот, целое поле | Непонятная карта вместо свайпа/линии |
| **Солитёр ассоциаций** | Карты/категории и узнаваемая связь | Персонаж крупнее карточного поля |

Эти пункты — **гипотезы для текущей проверки**, а не утверждения, что в играх есть такие дефекты. Before/after и фактический статус надо получать из актуального consumer HEAD.
