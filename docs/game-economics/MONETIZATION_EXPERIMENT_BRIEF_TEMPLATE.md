# Карточка одного коммерческого эксперимента

Заполнять для конкретной игры по [Commercial Teardowns](COMMERCIAL_TEARDOWNS_2026-11-13.md). Это документ решения, не обязательная новая система аналитики. Не создавать пустую карточку для мелкого bugfix.

## Проблема и решение

- Игра, repository / branch / HEAD / build / store, runtime kit pin:
- Действующие продуктовые решения о помощи, выдаче и рекламе:
- Наблюдаемая проблема и конкретное состояние игрока:
- Источник идеи: URL / build / timecode / проверенный артефакт:
- Что действительно установлено у конкурента; что остаётся гипотезой:
- Один изменяемый фактор и почему он может принести деньги:
- Контроль и один вариант; точное содержание награды/предложения:
- Действие при отказе, no-fill, закрытии рекламы и восстановлении приложения:
- Стоимость реализации и будущего сопровождения; уже имеющийся API/аналитика:

## Измерение

- Единица, момент и способ случайного назначения; как сохраняется вариант:
- Кто входит в исходную когорту; какие фильтры заданы ДО воздействия:
- Срок набора и полный горизонт наблюдения; timezone / calendar vs 24h:
- Первичный показатель: накопленная выручка на всех исходно назначенных пользователей:
- Как доход связывается с единицей назначения и вариантом; что доступно в текущей интеграции:
- Источник дохода, момент регистрации, валюта, precision, покупки/возвраты; неизвестные и недействительные значения:
- Как исключаются повторные события, load-time значения и двойной учет дохода; полнота данных по вариантам:
- Расходы на привлечение и дополнительные переменные расходы:
- Диагностика: согласие → показ → помощь → следующее игровое действие:
- Возвраты, уходы, ошибки, возможное вытеснение других покупок/показов:
- Какая экономическая разница оправдывает сопровождение:
- Достаточность выборки и метод оценки неопределённости:
- Правило завершения и технические основания досрочной остановки:

## Проверка до реального трафика

- На контрольном и изменённом вариантах показаны реальные переходы состояния:
- Вариант не меняется внутри партии и сохраняется при обычном перезапуске:
- Одно право на reward выдаётся один раз; закрытие не подменяет callback награды:
- Отсутствие рекламы и отказ не блокируют обычную игру:
- Загрузка объявления, показ, reward и денежный доход имеют разные события:
- Проверено, что используемый SDK действительно отдаёт требуемые данные в нужный момент:
- Нет непредусмотренного изменения других правил, цен, сохранений и контента:

## Итог

**Решение:** внедрить / отклонить / продолжить сбор по исходному плану / переработать гипотезу.

**Фактические данные:** пользователи по вариантам, зрелость когорт, выручка, интервал неопределённости, ошибки и будущая стоимость. Отдельно отметить, если проведена только техническая проверка или качественный плейтест.

**Причинный вывод:** что именно позволяет утверждать дизайн исследования. Не сравнивать добровольно выбравших rewarded с остальными как случайные группы.

**Kit impact:** NONE / REUSE / IMPROVE / CANDIDATE / EXTRACTED. Конкретный общий контракт, источник и следующий шаг при наличии; игровые цены и политика остаются в consumer.
